# Riviera: The Promised Land (GBA) — обратный инжиниринг и карта проекта

Документ фиксирует всё, что известно о ROM, форматах и инструментах проекта,
и намечает путь к «восстановлению движка» и порту на Android.

---

## 1. Платформа и ROM

| Параметр | Значение |
|---|---|
| Платформа | Game Boy Advance, ARM7TDMI (ARMv4T + Thumb) |
| ROM | `Riviera - Promised Land (U) [!].gba`, 32 000 000h байт (32 МБ) |
| Заголовок | title `RIVIERA`, game code `BREE`, maker `EB` |
| Точка входа | `EA00002E` (ARM branch) |
| Текст | однобайтовая таблица + управляющие коды, указатели 24-бит |
| Шрифт | 4bpp-тайлы 10×10, палитра 16 цветов |

Проверка: `python -c "d=open('rom.gba','rb').read(); print(d[0xA0:0xB0])"`.

## 3. Шрифт

### 3.1 Формат

- `Font.png`: 160×120, 16 тайлов в ширину × 12 в высоту, тайл 10×10, 4bpp.
- Палитра: `0` прозрачный, `2` тень (96,96,96), `6` тело (248,248,248).
- Раскладка: 0–32 `А..Я`, 33–65 `а..я`, 66–89 пусто, 90–99 цифры,
  100–125 `A..Z`, 126–151 `a..z`, 152–179 пунктуация.
- Базовая линия: заглавные — строки 1–7, строчные — 3–7, выносные — 8.

### 3.2 Адреса в ROM

| Что | Смещение | Размер |
|---|---|---|
| Тайлы шрифта | `0x58B400` | 9000h (180 тайлов × 50 байт) |
| Ширины глифов | `0x1031450` | 180 байт (по 1 на тайл, 1–10) |

### 3.3 Патчи кода, которые ставит `Font_Inserter.py`

| Смещение | Байты | Смысл |
|---|---|---|
| `0x1B878` | `B3` | правит константу/флаг шрифта |
| `0x1B890`–`0x1B891` | `56 FF` | расширение диапазона тайлов |
| `0x1B90C`–`0x1B90D` | `56 FF` | то же для второго пути |
| `0x1B910`–`0x1B912` | `50 14 03` | правка загрузчика палитры/атласа |
| `0x1B9DD`–`0x1B9DF` | `20 70 47` | `mov r0,#0x20; bx lr` — заглушка проверки |

Точный смысл патчей не документирован автором исходного инструмента; они
позволяют движку видеть кириллицу в младших тайлах и не сбрасывать её при
переключении банков.

## 4. Текст

### 4.1 Кодирование

- Русские буквы — однобайтовые коды `AA..EB` (см. `Insert/IN.tbl`).
- Латиница — двухбайтовые последовательности (`A2 XX`).
- Пробел — `8A`.
- Управляющие коды (строки в таблице): `A9=<line>`, `FE00=<Next>`, `FF=<End>`,
  а также параметрические `<XX>`, `<YY>`, `<$XX>` (сырой байт).
- Конец строки — `FF` (`<End>`), перенос — `A9` (`<line>`), смена блока — `FE00`.

### 4.2 Скрипты Atlas

```
#JMP($0F0000,$0F1234)      ; бюджет блока текста в ROM
#W24($0F0123)              ; адрес 24-битного указателя на строку
//The resting place of<line>the Grim Angels...<End>
```

`insert_custom.py`:

1. читает `#JMP` (границы блока) и все `#W24` + следующие `//` строки до `<End>`;
2. переводит строку по `translations.json`, кодирует по `IN.tbl`;
3. **дедуплицирует** одинаковые закодированные строки (ключевое отличие от Atlas,
   который писал каждую копию и переполнял блок);
4. пишет текст в блок и 3-байтовые указатели little-endian.

Именно дедупликация сняла ограничение «out of space»: словарь имён/предметов
повторяется сотни раз.

## 5. Что уже изменено в ROM

1. Шрифт: 180 тайлов с кириллицей в `0x58B400`.
2. Ширины: таблица в `0x1031450`.
3. Пять патчей кода (см. §3.3).
4. Все 40 блоков текста перезаписаны переводом (указатели + строки).
5. Оригинальные данные вне текстовых блоков не тронуты.

Сборка: `Insert/TPL.gba` (шрифт+патчи) → `Insert/TPL_translation.gba` (текст).

## 6. Что известно о движке

- Код — ARM/Thumb без символов; точка входа `0x08000000`.
- Скриптовая система: поток байт-кода, строки подставляются по 24-битным
  указателям; коды `A9/FE/FF` — управление выводом (перенос/новая страница/конец).
- Рендер: тайловый (BG/OBJ), шрифт грузится как 4bpp-тайлы в VRAM, ширины
  читаются из ROM-таблицы.
- Ассеты: графика/звук в стандартных GBA-форматах (LZ77-сжатие, pal, raw).
- Скрипты сцен/боя — отдельные байт-код-потоки; часть строк зашита «сырыми»
  байтами (титры), часть — графика (логотип).

## 7. Путь к Android

### Вариант A. APK-обёртка с ядром mGBA (быстро, реалистично)

- Взять libretro-ядро mGBA (ARM) + простой фронтенд (Kotlin/Java + JNI).
- APK не содержит ROM: пользователь кладёт свой `TPL_translation.gba`.
- Итог: играбельный APK за 1–2 недели, без «порта движка».
- Ограничения: это эмулятор, а не нативная игра; управление — экранные кнопки.

### Вариант B. Статическая рекомпиляция / декомпиляция

- Ghidra с процессором `ARMv4T` (ARM + Thumb), база `0x08000000`.
- Нет готового декомпилятора GBA→C; объём кода — сотни функций, включая
  скриптовую ВМ, рендер, звук, меню.
- Реалистичный минимум: найти и заменить **скриптовую ВМ** и **рендер текста**,
  оставив остальное эмулятором (HLE-подход).
- Для компиляции под Android: C-код + NDK (arm64-v8a), замена GBA-регистров
  на SDL2/OpenGL ES.

### Вариант C. Ремейк на Godot (долго, но переносимо)

- Извлечь ассеты (графика/звук/скрипты) из ROM, написать парсеры.
- Воспроизвести боевую систему и сюжетные сцены.
- Месяцы работы; зато нативный Android/PC.

### Что нужно для «восстановления движка»

1. **Дизассемблер**: Ghidra (ARMv4T), скрипты автоанализа, карта функций.
2. **Отладчик**: mGBA (`-d`) или no$gba — точки останова на чтение указателей
   строк, на вывод тайла, на диспетчер скриптов.
3. **Трассировка скрипт-ВМ**: найти обработчик байт-кода (по кодам `A9/FE/FF`),
   восстановить набор опкодов и формат сцен.
4. **Форматы ассетов**: LZ77 (BIOS `SWI 0x12`), pal, tilemap; звук — Direct Sound.
5. **Сборка**: devkitARM для тестовых сборок; NDK для Android-порта.

Практичный порядок: A (APK-эмулятор) → HLE-ядро для текста/скриптов →
постепенная замена подсистем → нативный порт.
